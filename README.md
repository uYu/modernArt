# 现代艺术 · Modern Art

中文浏览器桌游，3–5 人，你与 2–4 位本地 AI 经营美术馆，进行完整四季拍卖。React + TypeScript + Vite，画作为本地保存的 AI 生成油画图片，不需要账号、模型 API 或外部图片服务。

## 运行

Node.js 22.13+。

```bash
npm ci
npm run dev
npm run dev:api  # 另一个终端启动回放服务
```

默认地址为 http://127.0.0.1:5173；指定端口可用 `npm run dev -- --port 5174`。

```bash
npm test              # 规则回归 + 90 局 AI 自对战
npm run build         # 类型检查 + 生产构建
npm run format:check  # 格式检查
npm run preview       # 预览生产构建
```

## Docker 部署

服务器安装 Docker 和 Docker Compose 插件后，在项目根目录执行：

```bash
docker compose up -d
```

首次启动会自动构建镜像。访问 `http://服务器IP:8201`，本机为 `http://localhost:8201`。云服务器需要放行 TCP 8201。

部署包含 Nginx 静态网页和 Node 22 回放 API 两个容器。SQLite 数据保存在 Compose 的 `replay_data` 卷中；画作和 AI Worker 都已打包，不需要在服务器安装 Node 或手动运行 `npm ci`。上传项目源码与 `public/` 即可，不要上传 `node_modules/`、`dist/`。

```bash
# 更新源码后重新构建并启动
docker compose up -d --build

# 状态与日志
docker compose ps
docker compose logs -f web

# 停止并移除容器
docker compose down

# 8201 已占用或希望使用其他端口
PORT=18201 docker compose up -d
```

也可以在项目根目录的 `.env` 中写 `PORT=18201` 固定端口。默认重启策略为 `unless-stopped`，容器带有 HTTP 健康检查。首次构建需要能访问 Docker 镜像仓库和 npm 仓库。

进行中的存档仍保存在访问者的浏览器里。完成的对局会自动提交到服务器的 SQLite，并在主页「公开对局回放」供所有访问者浏览；同一对局重复提交会去重。重建容器不会删除数据卷，`docker compose down -v` 会删除公开回放。更换域名、协议或端口属于不同浏览器存储空间，进行中的存档需要先导出再导入。

## 操作

- 主菜单选择 3 / 4 / 5 人开局，随机先手；每馆初始 100 千元。
- 主菜单「美术展」可按画家浏览全部 70 幅作品；「公开对局回放」可浏览服务器保存的已完成对局。
- 成交提醒可在设置中切换：默认简短提醒 2 秒，或弹框确认后继续。一口价成交（含双画一口价）始终显示定价者、买家和价格，手动确认后继续，避免 AI 连续操作一闪而过。侧栏保留最近成交，可回看买家、作品、总价与卖家。双重拍卖注明两幅合计；季末未成交牌不触发成交提醒。
- 轮到你出画时，在手牌中选择作品，点击底部“确认出画”。艺术家色点可筛选手牌。
- 收藏家有独立的大桌面区域，区分“本场卖家”和当前行动者。中央拍品旁持续显示拍卖师姓名，双重拍卖接任后同步更新。
- 底部操作区按阶段显示出价、秘密报价、定价、购买或补画。选择和输入可以修改，提交后不可撤回。
- 公开竞价采用顺时针询问加价的异步交互；暂不加价不会永久退出，每次新报价都会重新询问其他所有玩家。无人再加价才成交。原桌游允许任意顺序喊价，此处明确采用顺序询问。
- 暗标逐人锁定但不显示任何金额，全部提交后统一揭晓。0 表示不报价。
- 艺术家区域仅显示已结算的历季定价，不显示本季出画数量、实时排名或预估售价。各收藏家藏品逐张陈列，由玩家自行判断行情。
- 第五幅作品亮相时立即结算，结算页手动确认后进入下一季；第四季结束公开所有玩家财富。
- 菜单可暂停、调节 AI 速度、导入导出存档及返回主菜单。打开设置或规则时 AI 自动暂停推进。
- 记牌面板分为现金、各季出牌、剩余牌三个页签。点击某季某画家的数量可查看作品、买家、卖家、成交总价及季末未成交标记；`5(1)` 表示出牌 5 张，其中 1 张季末未成交。
- 顶栏可开启“记牌辅助”：仅辅助记忆公开信息：根据公开交易与结算推算现金，回顾各季买入作品，并用牌组总量减去已亮相牌统计剩余牌。不展示对手手牌、未发牌堆构成或秘密报价，也不区分剩余牌的位置。面板打开时 AI 暂停；关闭记牌辅助后恢复隐藏信息。刷新或开始新局默认关闭，不影响 AI 的信息权限。
- 每步自动保存到浏览器 localStorage。刷新后从主菜单继续，未完成的拍卖和暗标均可恢复。损坏存档不自动删除；导入失败不替换当前游戏。新局和成功导入会替换自动存档。

## 规则与实现范围

- 五种拍卖、拍卖师自购向银行付款、其他买家向拍卖师付款；资金流向逐笔记录。
- 双重拍卖须搭配同一艺术家的非双重卡。其他人补画后接任拍卖师并收取全部款项，随后从接任者之后继续。
- 第五幅作品本身不成交，仍计入排名；若为双重的第二幅，两张均不成交。第一幅就触发则不进入补画。
- 以数量排名，平局按艺术家从左到右的固定优先级；前三名本季增加 30 / 20 / 10，出售价格叠加历史奖励。未入本季前三名的作品价值为零。
- 每季所有藏品出售弃置，手牌保留；补牌数量按人数为 3 人 10/6/6/0、4 人 9/4/4/0、5 人 8/3/3/0。
- 无手牌者跳过出画但仍可竞价；所有玩家手牌耗尽时最后拍品不成交，结算后结束游戏。
- 现金相同的最高财富玩家并列胜利。
- 不含三人“神秘玩家”可选变体、真人联机或困难搜索 AI。

规则依据：[CMON 官方规则书](https://www.cmon.com/wp-content/uploads/2023/06/MA_Rulebbok_Artbook_v18-low.pdf)。70 张牌的艺术家数量为 12/13/14/15/16，拍卖符号数量采用经典版[牌组分布表](https://www.scribd.com/document/960437945/Modern-Art-Card-Count)，数据集中在 `src/game/data.ts`，方便按其他版本调整。

## AI 与存档

默认 AI 为 `market-v3`：用24个未知牌场景比较出牌、补牌和季末结算；竞价保留稳定基线，加入卖家机会成本与公开竞价最小加价。完整模拟竞价在混合对手实验中回退，因此未启用。原算法保留在 `src/game/ai-legacy.ts`。

AI 只接收自己的信息、公开场面及已经公开的事件，能够通过公开交易记账，但不读取对手真实现金、手牌、牌堆种子或未揭晓暗标。网页在 Web Worker 中计算，暂停会取消计算，失败/超时回退旧策略。存档兼容。

已完成1,440局独立新版对战与匹配旧版对照，对旧版的3/4/5人胜率为63.9%/41.0%/32.2%；混合对手的3人提升未达到统计确认。完整结果、失败版本、限制和复现命令见 [AI实验报告](docs/ai-experiment-report.md)。

现金统计与 AI 公开记账共用结构化成交记录，不依赖日志文案；秘密报价揭晓前不进入成交记录。旧存档重放时自动恢复交易记录和季末未成交作品。

存档只保存开局参数与完整行动序列，载入时由规则引擎重放并验证。版本号为 1，导入设有体积和行动数量限制。存档是本地单人格式，包含隐藏信息的可重建数据，不适用于真人防作弊。

## 结构

- `src/game/engine.ts`：纯状态转换、合法性校验、结算、AI 可见信息、守恒检查。
- `src/game/types.ts` / `data.ts`：状态、行动、牌组和艺术家数据。
- `src/game/ai.ts`：普通 AI 策略。
- `src/game/storage.ts`：存档重放与验证。
- `src/components/Artwork.tsx`：按卡牌编号加载 `public/artworks/` 中的 70 幅独立油画；每位艺术家保留各自的题材和色调。
- `src/App.tsx` / `style.css`：菜单、行情、拍卖台、手牌、结算及自适应布局。
- `tests/engine.test.ts`：规则边界、信息隔离、资金流转和完整自对局。

自动测试在每步检查 70 张卡不重复、不丢失，玩家现金非负且符合银行净流量，市场计数与桌面作品一致；90 局覆盖三种人数及所有拍卖类型，终局存档重放须与原状态完全相同。

## 画作

画作使用内置 imagegen 生成，为虚构艺术家创作的油画风格图片，并非历史名画的扫描件。70 张牌各有一幅独立画作；牌面显示艺术家颜色、姓名与拍卖方式。原始生成图保留在生成目录，项目使用压缩后的本地 JPG。最初 15 幅的提示词和素材对应关系见 `public/artworks/prompts.json`。

### 公开竞价节奏

AI 公开竞价按剩余估值空间的四分之一加价（向上取整，每步 1–10 千元），不超过原有估值和现金上限；接近上限时自然缩小步幅。卖家仍比较自购与卖出的收益。

复现实验：`node --experimental-strip-types experiments/jump-bids.ts`。30 局生成的 240 个相同拍卖起点中，平均加价次数由 35.22 降至 9.00，总行动数由 44.72 降至 15.10，平均成交价由 35.22 变为 35.61 千元；11 场买家发生变化。此实验测量拍卖节奏与价格影响，不代表整局胜率提升。完整数据在 `experiments/jump-bids.json`。

## 交互、指南与复盘

- 出价区提供最低加价、+5、+10；暗标/定价可归零。输入错误会解释原因，并显示成交后的剩余现金。
- 操作栏参与页面布局，手牌和拍卖台不再被固定高度裁切；窄屏采用纵向布局。可在设置中关闭阶段规则提示。
- 「玩法指南」按如何开始、五种拍卖、季末算钱、操作与疑问分章，包含资金流向、双重拍卖接任和完整结算例子。对局中可直接跳到本场拍卖规则。
- 季末「藏品清算」与「现金净增」分开显示，自己的卖画收入、买画支出和清算收入逐项列出。
- 终局可打开「赛后复盘」：逐步/逐场重放、财富曲线、终季出牌跳转、逐笔买画盈亏；双画按整笔交易计算。
- 「同一发牌再挑战」保留发牌种子、先手和 AI 配置，并备份原局。重赛前已知信息不会被抹去，适合练习。
- 设置中的存档管理提供三个独立槽位；覆盖已有槽位需再次点击。载入、导入和同牌重赛前备份当前对局，可在存档管理中恢复。新局仍会替换自动存档。
- AI 节奏、成交提醒、阶段提示和新局选项保存在浏览器中。记牌辅助仍在刷新/新局时默认关闭。

## 对手难度

新局只选择入门、中等、困难、专家，默认入门。难度影响判断与规划，而不是统一压低报价。

- 入门：按作品价值正常竞买、正常定价；估值有可重现的 ±30% 判断误差，选画主要关注自己的藏品和眼前收入，不比较对手财富，也不作场景推演。
- 中等：稳定估值，采用局部选画评估，竞价使用稳健策略，包括卖家自购与卖出收入的比较。
- 困难：在任一画家亮相达到三幅或第四季时，启用抽样选画与补画；平时使用局部选画。
- 专家：所有选画与补画都使用 24 场景推演。竞价仍采用经过对照的 market-v3.1 稳健策略，不再把尚不稳定的自适应竞价直接当作专家。

难度更高并不等于每次喊价更高。所有难度遵守同样的信息权限和资金规则。配置随存档保存；带四档 `level` 的存档续局使用更新后的对应策略，不带 `level` 的早期存档保留旧算法以兼容。

旧的低价弱对手实验已不代表当前入门。当前相邻档位对照与限制见 [难度平衡报告](docs/difficulty-balance.md)。
