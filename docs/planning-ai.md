# 完整模拟与 ISMCTS 实验版

2026-09-20。已实现并可在新局菜单试玩；仍属于实验策略。正式「专家」的当前拍卖决策后来升级为 [统一拍卖搜索](universal-auction.md)，本页先导结果不包含这次升级。

## 怎么试玩

启动 `npm run dev`，选择「进入拍卖厅 → 对手难度」：

- **实验 · 完整模拟**：候选出牌分别按真实规则模拟到终局，按平均胜利分选牌。
- **实验 · ISMCTS**：使用相同模拟器和对手池，在自己的信息集上建立搜索树，用 UCB 分配模拟次数。

两个模式只接管出牌和补牌；竞价沿用现有稳健策略。选择随配置保存，存档可重放。每步最多 96 次完整模拟、约 250ms 软时间预算；只在两次完整模拟之间检查时间，因而可能略超预算。原来的 3 秒 Worker 看门狗继续有效。

时间预算会随机器负载改变完成的模拟次数，因此试玩动作不保证跨设备一致；固定种子和固定模拟次数的离线评测可复现。真实存档保存动作，不依赖重新运行搜索。

## 实际实现了什么

`src/game/ai-planning.ts` 包含：

1. `sampleWorld`：只从 Observation 构造合法隐藏世界，排除亮牌和自己手牌，按对手手牌数量无放回抽样，剩余牌保留为后续发牌堆。现金从公开账本推导。
2. 已锁定但未公开的暗标从对应模拟玩家的策略生成，不访问真实报价，也不会传给其他模拟玩家。
3. 未来成交、卖家自购、双重接任、第五张、现金和藏品变化、补牌、跨季结算全部调用同一规则引擎。
4. 对每个模拟玩家只调用 `observe` 后的策略；保守、标准、激进报价风格按场景抽取，与座位独立，整条模拟内固定。出牌延续策略目前都用旧版局部选画，所以这仍是有限对手池。
5. 终局奖励：单独第一为 1，并列第一分摊，落败为 0。
6. 返回动作、实际模拟数、耗时和各根候选的访问次数、平均终局奖励。尚未把这些调试统计显示在普通游戏界面。

`engine.ts` 增加 `advanceSimulation`，在可丢弃的模拟状态上原地推进，避免每一步深拷贝；规则逻辑与真实 `applyAction` 共用同一个 `transition`。模拟状态丢弃回放动作和日志字符串，保留交易和结算。测试逐步对照两条路径，验证除这些记录外完全一致。

模拟器历史结果中的收入采用累计充分统计表示，目的是正确推导观察和未来价值；不代表真实历史回放。模拟世界不能作为游戏存档使用。

## ISMCTS 的具体范围

这是**单观察者信息集树搜索，对手采用固定策略混合**：

- 每次迭代重新抽取一个隐藏世界。
- 根节点使用 UCB；后续只在当前玩家再次行动时搜索。
- 节点键仅使用当前玩家自己的观察，不含模拟对手私有手牌或隐藏报价。
- 每次迭代最多扩展一个新信息集，最多搜索自己的四次选择，余下部分由延续策略运行到终局。
- 最终动作按访问过的根候选的平均胜利分选择，平分时优先访问次数更多者。

它不是所有玩家同时优化的均衡求解器。完整观察作为节点键可能使搜索树较稀疏；48–96 次模拟分给多个候选后，每个候选只有少量样本。需要后续测量树复用率和估值方差，再决定信息抽象或价值函数，不应仅因算法名字更复杂就宣称更强。

出牌中同艺术家、同拍卖方式的重复牌合并为一个等价动作。竞价候选生成器已支持抽象价位，但当前产品和对战实验仍保留原竞价，避免一次性改变多个模块。

## 固定模拟数先导结果

2 个种子 330001–330002，3/4/5 人轮换全部待测座位；每局一个待测策略，其余全为困难。三个版本均使用相同发牌与先手。每次实验搜索 48 次完整模拟，不设置时间上限。共 72 局。

| 人数 | 每个版本局数 | 当前专家胜利分率 | 完整模拟 | ISMCTS |
| ---- | -----------: | ---------------: | -------: | -----: |
| 3    |            6 |            33.3% |    33.3% |  33.3% |
| 4    |            8 |            37.5% |    12.5% |   0.0% |
| 5    |           10 |            10.0% |     5.0% |  20.0% |

这里的 5% 包含并列胜利分摊。仅两个种子，不能从某一组结果推断强弱排名，更不应计算看似精确的独立对局置信区间。四人局结果已足以提醒我们保留实验标签，不把新算法直接替换专家。

选牌/补牌平均耗时：专家约 1.4–2.0ms，完整模拟约 249–356ms，ISMCTS 约 220–354ms；新算法单次最大耗时分别约 643ms、606ms。这是当前机器 Node 进程中的测量，部分时间有测试/构建并发，不代表独占机器或浏览器端性能。

原始结果：[planning-pilot.json](../experiments/planning-pilot.json)。含每局资金、胜利分、座位、种子、耗时、模拟数以及运行时源码哈希。开始实验后新增了 UI 路由，原专家和搜索核心在这批运行中没有改变；结果以记录的哈希为准。

## 复现

```sh
# 完整固定次数先导实验；输出文件可自行指定
node --experimental-strip-types experiments/planning-benchmark.ts 330001 2 48 /tmp/planning-pilot.json

# 统一软时间预算，两种搜索都是最多 96 次、250ms；另用一个种子
node --experimental-strip-types experiments/planning-benchmark.ts 340001 1 96 /tmp/planning-time-pilot.json 250

# 针对性测试；全量回归和构建
node --experimental-strip-types --test tests/planning.test.ts
npm test
npm run build
```

基准脚本每完成一个种子的全部座位写入结果，记录文件可辨认是否跑完。它检验每一步卡牌、资金守恒和最终终止；目前对手只用困难，不构成跨对手稳健性验证。

## 下一步应做什么

先定位有限预算下的误差来源：记录有效候选数、每候选样本数和树复用率；将延续对手从旧版局部选牌扩展到当前困难/终季策略；在冻结的小型诊断集比较 48/192/768 次模拟与不同深度。高预算仅作离线诊断，不能把更长计算的收益当作同时间胜出。

把明确可直接获胜的终季动作做精确优先处理，并研究带先验的候选筛选与价值函数，以减少跨四季模拟的方差。以上改动需独立消融，之后换未使用的种子和混合对手验收。当前不支持“已经比专家更强”的结论。

## 同时间预算补充实验与交付验证

另用种子 340001，两个搜索统一为最多 96 次、250ms 软预算，轮换所有座位，共 36 局。该实验与前面的固定 48 次实验配置不同，不能合并成同一胜率估计。

| 人数 | 每版本局数 | 当前专家 | 完整模拟 | ISMCTS |
| ---- | ---------: | -------: | -------: | -----: |
| 3    |          3 |    33.3% |    33.3% |  66.7% |
| 4    |          4 |     0.0% |    25.0% |   0.0% |
| 5    |          5 |    20.0% |     0.0% |  60.0% |

只有一个种子，结果波动极大；这些点估计不能用于声称 ISMCTS 超越专家。两种搜索的平均选牌耗时约 225–244ms，符合软预算设计；专家未人为消耗同等时间。

原始结果：[planning-time-pilot.json](../experiments/planning-time-pilot.json)。由于以墙钟时间停止，模拟数和动作可能随负载变化，文件记录每局实际模拟次数。
